## OP-001：将轮询所有权领取线性化

证据：`src/resource/cleanup_scheduler/cleanup_task.rs:84–117`。`CleanupResponsibility::task` 和 `CleanupScheduler::task` 可以返回共享同一 `CleanupTaskState` 的不同观察者。每个观察者虽然以 `&mut self` 调用，仍可在不同线程操作同一共享状态。

现有交错：A 和 B 都在第一锁区间看到 `settled=false, polling=false`；A 在后续锁区间取走 future；B 随后不重新检查状态，执行 `take().expect(...)`，在捕获用户 future panic 的边界外 panic。A 已完成时 B 继续领取同样不安全。

选择最小方案：在一个 `inner` 锁区间完成 `settled`、`polling`、deadline 域与首次超时观察判断，以及 `future.take()` 和 `polling=true`。随后释放锁，执行用户 future 的 poll，并沿用 `finish_poll` 的 Pending 恢复与完成路径。保持判断顺序：已完成优先返回 AlreadySettled；已有轮询者返回观察值 Pending；随后处理域不匹配和首次 Unconfirmed；最后才领取 future。

不选择让锁覆盖 future.poll：用户代码可能重入或耗时，会引入死锁风险。不选择禁止多观察者或增加公共所有权 token：会改变已公开的重新取得任务能力，且不需要破坏 API 就能修复。

不变量：

- 未完成且未被轮询时，future 保存在共享状态中。
- 轮询者获得 future 与标记 polling 属于同一原子转换；其他观察者不能再领取。
- future.poll 和 future 的析构继续在状态锁外执行。
- Pending 后恢复 future 并清除 polling；完成后只走一次 complete_task，permit 只释放一次。
- 不修改 `poll_at` 的返回类型：外层仍为 Ready，内部 CleanupObservation::Pending 表示尚未完成；不新增唤醒保证。

测试设计：两个独立观察者，共享受控 future；用 Barrier/channel 控制领取竞争、保持某观察者正在 poll，以及完成先于另一方领取的交错。断言无 panic、最大同时 poll 数为 1、future 析构一次、active 从 1 变为 0，完成后再观察得到 AlreadySettled。测试不得以 sleep 或随机压力作为唯一复现方式。为稳定暴露旧版本“检查与领取之间”的窗口，可在单元测试配置中加入窄范围的领取前同步钩子：旧逻辑放在第一次检查后、最终领取前；修复后放在整个原子领取区间之前。钩子不在持锁时阻塞，不进入公共 API 或发布构建。优先使用现有测试设施，只有不足时增加该钩子。补充 deadline 首次 Unconfirmed、错误时钟域以及 panic/permit 的既有语义回归。

## OP-002：示例只断言稳定事实

证据：`src/driver/portable_driver.rs:44–45` 提交 `async {}` 后断言 task_count 为 1，任务可能已经执行完而为 0。

保留异步空任务和非零 TaskHandle 断言，删除瞬时数量断言，用英文说明 worker 可在 spawn 返回后立即完成，task_count 只是当前快照。无需为展示数量额外引入阻塞 gate，也不更改 task_count 语义。运行该类型的 doctest，再由集成任务运行全量 doctest。

## OP-003：英文指南具备独立可用性

证据：英文 `doc/user_guide.md` 是概述；中文 `doc/user_guide.zh_CN.md` 已包含配置、转移、恢复、服务资源和关闭后观察等操作路径。

以当前代码和双语文档为共同事实源，增量完善英文指南，不覆盖用户已有内容。允许语言自然表达、段落结构不同，但应覆盖相同的核心能力、错误边界和操作步骤。至少包括：

1. MIME 输入登记与租约的完整公开 API 示例；说明这是内存练习，以及真实文件和命令适配器各自承担的责任。
2. 创建 supervisor、准入拒绝时取回未执行闭包、ScopeOptions 和上下文、结果一次性读取与收尾重复观察。
3. 取消、丢弃、detach、结果内资源租约的等待环，以及资源转移失败后仍由源作用域持有。
4. 子操作 reserve/attach/commit 与副作用先后顺序、必要／可选子操作和 FailFast／Collect。
5. 资源登记、cleanup_after、转移依赖组、恢复表 key 的保存和取回，以及清理 panic 的独立 capsule 边界。
6. PortableDriver、ThreadExecutor 和 ExternalDriver 的运行环境约束；服务组长期资源、关闭超时后的观察与 pending 处理。
7. 容量、期限、类型化错误、诊断和按症状排障；说明 Released、RecoveryRequired、Unconfirmed 的不同应用决策。

每条主路径给出必要对象、调用顺序、成功信号和失败后的处理方向；对应能力已有完整示例时链接，但不以链接代替基础调用链。按当前 API 核实代码，完整示例在仓库外临时验证工程使用本地源码验证，交付指南中的依赖写 `qubit-operation = "^0.1"`。中文版仅在事实纠正或导航同步确有需要时调整，README 仅在入口失配时调整；不重写整个 README，不新增领域服务实现。
